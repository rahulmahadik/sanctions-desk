# Known issues

Problems met while building this, with what was done about each. Facts only; versions are the ones used during development (Zetaris 2.4.x local, Nightshift runtime 1.4, Ollama with `nemotron-3.5-lightning:30b`).

## Models and the Nightshift runtime

| Issue                                                    | What happens                                                                                                                                                                            | Workaround in this repository                                                                                                                                                                                                                                                                                                         |
| -------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| A model route is retired                                 | A mode or cloud function that used to answer returns HTTP 410, `class_no_route` or a "Function not found" 404 wrapped in a 502                                                          | The generator treats these as a dead route, tries the next configured mode once, then the Ollama backup. Every attempt is reported with the mode asked for and the model that answered. The cloud lanes were pointed at Nemotron 3 Ultra                                                                                              |
| Lane choice is not ours                                  | Chat requests are served as the runtime's own `auto` mode whatever pinned mode is asked for; there is no setting to force local or cloud for one call                                   | The code always asks for a pinned mode (`meterless/auto` is rejected), and records both what was asked and what answered (`model_requested`, `model_routed`, `route_kind`) so the choice can be seen, not assumed                                                                                                                     |
| Answers repeated from a cache                            | A prompt the runtime has answered before comes back in milliseconds with `from_cache: true`                                                                                             | Evaluation runs use a separate app id (`METERLESS_EVAL_APP_ID`); cached answers are excluded from latency figures                                                                                                                                                                                                                     |
| Cloud reasoning leaks into the answer                    | The cloud model writes its reasoning before (or instead of) the JSON and can run out of tokens before reaching it. Four of 65 cases ended with no usable decision in the first full run | Reasoning is bounded and asked for with the JSON last; the last JSON object is taken. A failed first try is retried on the fast lane, then on the Ollama backup with JSON-only output. If all three fail, the case is escalated with the reason "model decision unavailable" and counted separately in the report; it is never closed |
| Slow route for "rejected" wording                        | A retry phrased as a rejection is sent to a much slower route, and the proxy gives up after about 47 seconds                                                                            | Retry notes are worded neutrally; reasoning budgets are small                                                                                                                                                                                                                                                                         |
| Decision spelled differently                             | A model writes `ESCALATE` or `Close` instead of the exact decision name                                                                                                                 | A fixed list of spellings is read as the same decision; anything else is rejected, not guessed                                                                                                                                                                                                                                        |
| No embeddings                                            | The runtime lists an embedding model but serves no route for it (`class_carrier_unsupported`)                                                                                           | Name matching is deterministic (see `docs/MODELS.md`)                                                                                                                                                                                                                                                                                 |
| Receipts are signed with a key sent in the same response | A receipt proves the answer was not altered, not who signed it, unless the key is pinned                                                                                                | `METERLESS_RECEIPT_PUBLIC_KEY` pins the key; status is `valid_pinned`, `valid_unpinned` or `invalid`                                                                                                                                                                                                                                  |

## Zetaris

| Issue                                                                | What happens                                                                                                                                                                                                                                                                                                                                                            | Workaround in this repository                                                                                                                                                                                                                         |
| -------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Every value is a string                                              | Numbers, dates and NULLs come back as JSON strings (NULL as `null`)                                                                                                                                                                                                                                                                                                     | The code casts explicitly; amounts and scores are parsed where they are used                                                                                                                                                                          |
| A column called `precision`                                          | It is stored with its backquotes and breaks the compiled model                                                                                                                                                                                                                                                                                                          | The column is called `dob_precision`                                                                                                                                                                                                                  |
| Cached tables outlive their database                                 | A cached REST table survived `DROP DATABASE`                                                                                                                                                                                                                                                                                                                            | The reset script releases it first (`UNCACHE TABLE`)                                                                                                                                                                                                  |
| One statement per call                                               | A semicolon makes the parser fail                                                                                                                                                                                                                                                                                                                                       | The SQL guard rejects it before sending                                                                                                                                                                                                               |
| Masking, row filters and the OpenAPI document                        | There is no SQL or REST call for column masks or row filters, and the OpenAPI document needs a sign-in with a password that the API key does not satisfy                                                                                                                                                                                                                | Masking is applied in the adapter as well; the interface step is documented in `docs/ZETARIS.md`                                                                                                                                                      |
| Creating users                                                       | There is no `CREATE USER` in SQL. `POST /users` works; `PATCH /users/{email}` accepts a new password and leaves the account unable to sign in                                                                                                                                                                                                                           | `npm run zetaris:agents` drops and recreates the users, then issues each user's API key through the web interface's own sign-in and `POST /auth/api-key` calls (undocumented)                                                                         |
| A role needs a permission, not only grants                           | The three runtime users were refused every table of the model ("does not have access to USL") although table-level `SELECT` grants existed. The platform's permissions guide says a non-admin role also needs the View permission on the Unified Semantic Layer under Management → Permissions, which is an interface setting with no SQL form in the command reference | Until it is set and verified, a refused role token is replaced once by the admin key, visibly (`token_source: fallback`), and the role token is not tried again for that process. See "Access control" in `docs/ZETARIS.md`                           |
| The id_number column policy is HIDE, not a mask, and is not enforced | This edition offers GRANT, DENY and HIDE on model columns and no pattern mask. With HIDE set for the evidence role, its token still receives `id_number` in clear                                                                                                                                                                                                       | The application masks the number in the adapter and the interface (`••••`) and compares identifiers inside Zetaris so the number is never read into the application. A live test marked as an expected failure flags the day the platform enforces it |
| Grants and rebuilt models                                            | Grants are recorded against a model by internal identifier; a rebuilt model can leave roles that look granted but cannot read                                                                                                                                                                                                                                           | Roles and grants are left in place across rebuilds and the live role check (`npm run test:live`) shows whether reads work                                                                                                                             |
| `EXPLAIN` and several metadata calls are admin-only                  |                                                                                                                                                                                                                                                                                                                                                                         | Plans are recorded once with the admin key (`docs/QUERY_PLANS.md`)                                                                                                                                                                                    |
| No MCP endpoint and no lineage read                                  |                                                                                                                                                                                                                                                                                                                                                                         | The adapter uses REST; evidence is tied to Zetaris's own statement history by query id                                                                                                                                                                |
