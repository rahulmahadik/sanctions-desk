# Known issues

Problems met while building this, with what was done about each. Facts only; versions are the ones used during development (Zetaris 2.4.x local, Nightshift runtime 1.4, Ollama with `nemotron-3.5-lightning:30b`).

## Models and the Nightshift runtime

| Issue                                                    | What happens                                                                                                                                                                                                                                                                                                                                                                                                                                                                   | Workaround in this repository                                                                                                                                                                                                                                                                                                                                                 |
| -------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| A model route is retired                                 | A mode or cloud function that used to answer returns HTTP 410, `class_no_route` or a "Function not found" 404 wrapped in a 502                                                                                                                                                                                                                                                                                                                                                 | The generator treats these as a dead route, tries the next configured mode once, then the Ollama backup. Every attempt is reported with the mode asked for and the model that answered. The cloud lanes were pointed at Nemotron 3 Ultra                                                                                                                                      |
| Lane choice is not ours                                  | Chat requests are served as the runtime's own `auto` mode whatever pinned mode is asked for; there is no setting to force local or cloud for one call                                                                                                                                                                                                                                                                                                                          | The code always asks for a pinned mode (`meterless/auto` is rejected), and records both what was asked and what answered (`model_requested`, `model_routed`, `route_kind`) so the choice can be seen, not assumed                                                                                                                                                             |
| Answers repeated from a cache                            | A prompt the runtime has answered before comes back in milliseconds with `from_cache: true`                                                                                                                                                                                                                                                                                                                                                                                    | Evaluation runs use a separate app id (`METERLESS_EVAL_APP_ID`); cached answers are excluded from latency figures                                                                                                                                                                                                                                                             |
| Cloud reasoning leaks into the answer                    | The cloud model writes its reasoning before (or instead of) the JSON and can run out of tokens before reaching it. Four of the 65 cases of an early run (the exam has since grown) ended with no usable decision in the first full run                                                                                                                                                                                                                                         | Reasoning is bounded and asked for with the JSON last; the last JSON object is taken. A failed first try is retried on the fast lane, then on the Ollama backup with JSON-only output. If all three fail, the case is escalated with the reason "model decision unavailable" and counted separately in the report; it is never closed                                         |
| Slow route for "rejected" wording                        | A retry phrased as a rejection is sent to a much slower route, and the proxy gives up after about 47 seconds                                                                                                                                                                                                                                                                                                                                                                   | Retry notes are worded neutrally; reasoning budgets are small                                                                                                                                                                                                                                                                                                                 |
| A model call that never got an answer                    | In the first full run seven decision/critic calls (six decision, one critic) and three challenger calls were logged as not schema-constrained. They were calls that ended before any answer because every provider failed; the log line for a failed call did not carry the schema flag, so they looked unstructured. None of the answers that did come back was unstructured. One challenger call also failed because it listed more than four points, the limit at that time | Failed calls now log the lane, the try and the schema flag. A pause (1.5 s times the try number) follows a provider failure, then the next lane is tried: own lane, fast lane, Ollama backup. The challenger may list up to eight points, strongest first, and a longer list is cut at eight instead of failing. The report counts calls that ended before any answer by lane |
| Decision spelled differently                             | A model writes `ESCALATE` or `Close` instead of the exact decision name                                                                                                                                                                                                                                                                                                                                                                                                        | A fixed list of spellings is read as the same decision; anything else is rejected, not guessed                                                                                                                                                                                                                                                                                |
| No embeddings                                            | The runtime lists an embedding model but serves no route for it (`class_carrier_unsupported`)                                                                                                                                                                                                                                                                                                                                                                                  | Name matching is deterministic (see `docs/MODELS.md`)                                                                                                                                                                                                                                                                                                                         |
| Receipts are signed with a key sent in the same response | A receipt proves the answer was not altered, not who signed it, unless the key is pinned                                                                                                                                                                                                                                                                                                                                                                                       | `METERLESS_RECEIPT_PUBLIC_KEY` pins the key; status is `valid_pinned`, `valid_unpinned` or `invalid`                                                                                                                                                                                                                                                                          |

## Zetaris

| Issue                                                                         | What happens                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      | Workaround in this repository                                                                                                                                                                                                                                                                                                                                  |
| ----------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Every value is a string                                                       | Numbers, dates and NULLs come back as JSON strings (NULL as `null`)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               | The code casts explicitly; amounts and scores are parsed where they are used                                                                                                                                                                                                                                                                                   |
| A column called `precision`                                                   | It is stored with its backquotes and breaks the compiled model                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    | The column is called `dob_precision`                                                                                                                                                                                                                                                                                                                           |
| Cached tables outlive their database                                          | A cached REST table survived `DROP DATABASE`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      | The reset script releases it first (`UNCACHE TABLE`)                                                                                                                                                                                                                                                                                                           |
| One statement per call                                                        | A semicolon makes the parser fail                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 | The SQL guard rejects it before sending                                                                                                                                                                                                                                                                                                                        |
| Masking, row filters and the OpenAPI document                                 | There is no SQL or REST call for column masks or row filters, and the OpenAPI document needs a sign-in with a password that the API key does not satisfy                                                                                                                                                                                                                                                                                                                                                                                                                                                                          | Masking is applied in the adapter as well; the interface step is documented in `docs/ZETARIS.md`                                                                                                                                                                                                                                                               |
| Creating users                                                                | There is no `CREATE USER` in SQL. `POST /users` works; `PATCH /users/{email}` accepts a new password and leaves the account unable to sign in                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     | `npm run zetaris:agents` drops and recreates the users, then issues each user's API key through the web interface's own sign-in and `POST /auth/api-key` calls (undocumented)                                                                                                                                                                                  |
| A role needs a permission, not only grants                                    | The three runtime users were refused every table of the model ("does not have access to USL") although table-level `SELECT` grants existed. The platform's permissions guide says a non-admin role also needs the View permission on the Unified Semantic Layer under Management → Permissions, which is an interface setting with no SQL form in the command reference                                                                                                                                                                                                                                                           | Until it is set and verified, a refused role token is replaced once by the admin key, visibly (`token_source: fallback`), and the role token is not tried again for that process. See "Access control" in `docs/ZETARIS.md`                                                                                                                                    |
| The id_number column policy is HIDE, not a mask, and is not enforced          | This edition offers GRANT, DENY and HIDE on model columns and no pattern mask. With HIDE set for the evidence role, its token still receives `id_number` in clear                                                                                                                                                                                                                                                                                                                                                                                                                                                                 | The application masks the number in the adapter and the interface (`••••`) and compares identifiers inside Zetaris so the number is never read into the application. A live test marked as an expected failure flags the day the platform enforces it                                                                                                          |
| A cached REST table is lost when the engine restarts                          | `CACHE TABLE` holds the payments table in the engine, not on disk. After a restart of the Zetaris engine every payments read calls the payments service again (slower, and it fails if the service is down)                                                                                                                                                                                                                                                                                                                                                                                                                       | `npm run zetaris:cache-check` reports it and, with `--apply`, caches the table again and logs the statement. The running application does not do this itself, because it never holds the admin key                                                                                                                                                             |
| A bind overrides the retry lane, and two copies of the local model are loaded | With the reasoning identity bound to `deep`, a retry on the fast lane is still served as deep (the receipt records `mode_mismatch`), so the second try goes to the same cloud lane as the first; in the held-out run four cases then ended with every provider failed. The Ollama backup keeps its own 19.5 GB copy of the local model (Nightshift holds another, about 24.6 GB resident) and loads it on demand, so the third try starts cold. The runtime also reported a serious thermal state and a reduced admission posture during long runs. Memory pressure was normal and swap under 200 MB, so memory was not the cause | The failed cases are escalated to a person (safe) and counted separately. Proposed, after the final runs: retry on the local (guard) identity instead of the same bound lane, record the provider error type in the trace, keep one local copy loaded (point the backup at the resident lane, or unload Ollama's copy), and avoid other heavy work during runs |
| The local model answers schema-constrained requests with nothing              | Asked for schema-constrained JSON (`response_format` of type `json_schema`), the local Nemotron 3.5 Lightning answered with an empty response: Nightshift returned HTTP 502 "empty_response" and the Ollama backup an empty answer, on every try. The free-text screener asked that way, so in the blind held-out v2 run (24 Oct 2026) it failed on every case, and by design a failed screener never allows a close. The cloud model answers such requests normally                                                                                                                                                              | Fixed after that run: the screener, a retry sent to the local model and the backup ask for plain JSON, checked against the same schema (commit `f6ed38a`). The blind run is reported unchanged; the same frozen cases were re-run after the fix and are labelled as such                                                                                       |
| Grants and rebuilt models                                                     | Grants are recorded against a model by internal identifier; a rebuilt model can leave roles that look granted but cannot read                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     | Roles and grants are left in place across rebuilds and the live role check (`npm run test:live`) shows whether reads work                                                                                                                                                                                                                                      |
| `EXPLAIN` and several metadata calls are admin-only                           |                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   | Plans are recorded once with the admin key (`docs/QUERY_PLANS.md`)                                                                                                                                                                                                                                                                                             |
| No MCP endpoint and no lineage read                                           |                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   | The adapter uses REST; evidence is tied to Zetaris's own statement history by query id                                                                                                                                                                                                                                                                         |

## Review logic

| Issue | What happens | Workaround in this repository |
| --- | --- | --- |
| Screener signals not grounded in their span (over-flagging) | On cases that should close, the local screener reported "relationship to listed party" at high confidence on a span whose text held no relation term and no name from the evidence (for example the first 30 characters of a note). The signal blocked a close although the note met the documentary standard. | Span grounding (policy version 7, `screener.grounding`): a signal counts only if its span lies inside the field, the span holds a term of its type (policy lists in seven languages), and a listed name, alias, customer or counterparty name is in the span or within 80 characters. A signal that is not grounded is kept with `grounded: false` and a reason, recorded, counted and shown, and does not block a close. Grounded signals block as before; the injection flag is unchanged. |
| A note's document number was not compared with the customer record | A note with a check reference, a document number and a date met the standard even if the number was not one of the customer's documents. | One count inside Zetaris under the evidence identity; only the count returns and the number is never logged (a hash is). A count of 0: "document cited in note not on customer record", the note does not meet the standard and a close goes to NEED_MORE_INFO. A count that cannot be made is "not verified" and fails closed. Sample mode has no saved answer for this count until the sample cache is recorded again, so there the check is "not verified". |
| Critic deadlock on citations that cannot be checked | The decision step cited sources the critic cannot verify by design (a free-text column, the identifier number column, blocks worked out by code cited as tables). The critic rejected the same citation in every round, the decision repeated it, and the case ended unresolved and escalated. | The decision prompt lists exactly which tables and columns can be cited (the critic's tables, without free-text columns or the identifier number; the computed blocks named as not citable). The critic's note says "remove this citation; it cannot be cited", and from the second round on it sets such citations aside as not citable (in the trace, the record and the review desk) and judges the remaining facts. A citable fact whose value does not hold is still a rejection, and the three-round limit stays. |
