# How memory, reasoning and tools work

The three engines each cover one part of the work:
- **Memory: H-MEM.** Each earlier decision, and each decision a person makes on the desk, comes in as its outcome, reason codes and a pointer to the row it rested on (table, key, content hash, list snapshot), never as a copy of the customer's details. Conflicts are handled two ways: before a memory may influence a review its pointer is re-checked against the data as it is now, and a changed hash makes it stale, so the case is looked at again instead of trusted (alert ALR-0058 in sample mode); and when two decisions on the same customer and listed party disagree, a person's later decision wins, and the trust ledger records who overrode a decision and why.
- **Reasoning: Markovian.** After a list change, every earlier decision is re-checked in bounded batches, carrying only a cursor and a running tally from one batch to the next; affected decisions are offered to a person for review.
- **Tool use: World Model.** The ownership register of the case, written into the World Model row by row with provenance and a validity date; the 50 percent rule (counted as a cascade) is evaluated on what it gives back.

All three pass the official conformance tests: H-MEM 13/13, Markovian 8/8, World Model 8/8. Not used by the app: H-MEM's tiered promotion (decision memories are written straight to long-term memory), its sleep cycle and dreaming, and its general conflict-detection service. These are in our engine code and pass the official tests, but the app does not use them; the lessons across cases are drawn by people after each review round (see [Evaluation](EVALUATION.md)).

## Meterless build: the engines

Three engines from the Meterless specifications are implemented in TypeScript (Apache-2.0, a "derived from the Meterless reference" header on every file) and each does real work in the product:

| Engine                          | What it does in the product                                                                                                                                                                                                                                                                                                                       | Where in the code                                                               | Used by                                                                               |
| ------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------- |
| **H-MEM** (hierarchical memory) | Remembers each earlier decision as its outcome, reason codes and a pointer to the row it rested on (table, key, content hash, list snapshot), never as personal data. On recall the pointer is re-checked: a changed hash makes the memory stale. A person's override beats memory, and the trust ledger records who overrode a decision and why. | `packages/engines/src/hmem/`, `packages/engines/src/domain/pointer-memory.ts`   | the memory step (`packages/agents/src/memory.ts`)                                     |
| **World Model**                 | The ownership step writes the register rows it reads through Zetaris into the World Model (`OwnershipWorld`), one edge per row with provenance and a validity date, and evaluates the 50 percent rule (a cascade, plus effective ownership) on the rows it gives back; it can also answer as of a past date.                                      | `packages/engines/src/world-model/`, `packages/engines/src/domain/ownership.ts` | the ownership step (`packages/agents/src/ownership.ts`)                               |
| **Markovian**                   | Re-screens earlier decisions after a list update, in bounded batches with a carried cursor: entries that changed are re-opened, removed ones are offered to a person for release.                                                                                                                                                                 | `packages/engines/src/markovian/`, `packages/engines/src/domain/rescreen.ts`    | list-change replay (`packages/agents/src/list-change.ts`, `POST /list-change/replay`) |
