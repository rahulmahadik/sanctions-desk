# Resolved issues

Problems met while building the desk, and how each was fixed or decided, and platform limits the desk now works around. Problems that are still true are in [KNOWN_ISSUES.md](KNOWN_ISSUES.md).

## Models and the Nightshift runtime

| Issue                                                    | What happens                                                                                                                                                                                                                                                                                                                                                                                                                                                                      | How it was resolved                                                                                                                                                                                                                                                                                                                                                                  |
| -------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| A model call that never got an answer                    | In the first full run seven decision/critic calls (six decision, one critic) and three challenger calls were logged as not schema-constrained. They were calls that ended before any answer because every provider failed; the log line for a failed call did not carry the schema flag, so they looked unstructured. None of the answers that did come back was unstructured. One challenger call also failed because it listed more than four points, the limit in that version | **Fixed.** Failed calls log the lane, the try and the schema flag. A pause (1.5 s times the try number) follows a provider failure, then the next lane is tried: own lane, fast lane, Ollama backup. The challenger may list up to eight points, strongest first, and a longer list is cut at eight instead of failing. The report counts calls that ended before any answer by lane |
| Receipts are signed with a key sent in the same response | A receipt proves the answer was not altered, not who signed it, unless the key is pinned. The Nightshift runtime's key is pinned in `config/default.json` (checked against the recorded receipts and a live one), so a receipt signed by another key fails; the key was first obtained from the runtime itself                                                                                                                                                                    | **Fixed: the key is pinned.** `METERLESS_RECEIPT_PUBLIC_KEY` pins the key; status is `valid_pinned`, `valid_unpinned`, `invalid` or `malformed`                                                                                                                                                                                                                                      |
| Nightshift added its own memory to calls                 | Nightshift 1.2.1 has an answer memory of its own, on by default and with no per-app switch; it was on during every recorded run (<!--fact:receipts_runs_memory-->1,483<!--/fact--> of <!--fact:receipts_runs-->2,092<!--/fact--> receipts in `eval/runs/` carry added memories), and could add local answers to cloud calls                                                                                                                                                       | **Fixed.** Switched off for the whole runtime after the recorded runs (`hmemKnowledge: false`); details in [docs/MODELS.md](MODELS.md#nightshifts-own-memory-switched-off)                                                                                                                                                                                                           |

## Zetaris

| Issue                                                                         | What happens                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      | How it was resolved                                                                                                                                                                                                                                                                                                                                             |
| ----------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| A bind overrides the retry lane, and two copies of the local model are loaded | With the reasoning identity bound to `deep`, a retry on the fast lane is still served as deep (the receipt records `mode_mismatch`), so the second try goes to the same cloud lane as the first; in the held-out run four cases then ended with every provider failed. The Ollama backup keeps its own 19.5 GB copy of the local model (Nightshift holds another, about 24.6 GB resident) and loads it on demand, so the third try starts cold. The runtime also reported a serious thermal state and a reduced admission posture during long runs. Memory pressure was normal and swap under 200 MB, so memory was not the cause | **Fixed after the recorded runs: a retry goes under the guard identity (`retryIdentity` in the policy).** The failed cases are escalated to a person (safe) and counted separately. The two local copies are still open: see [KNOWN_ISSUES.md](KNOWN_ISSUES.md#open-platform-limits)                                                                            |
| The local model answers schema-constrained requests with nothing              | Asked for schema-constrained JSON (`response_format` of type `json_schema`), the local Nemotron 3.5 Lightning answered with an empty response: Nightshift returned HTTP 502 "empty_response" and the Ollama backup an empty answer, on every try. The free-text screener asked that way, so in the blind held-out v2 run it failed on every case, and by design a failed screener never allows a close. The cloud model answers such requests normally                                                                                                                                                                            | **Fixed.** After that run, the screener, a retry sent to the local model and the backup ask for plain JSON, checked against the same schema (system sys2b; [re-run result](../eval/results/2026-10-23T19-34-36-325Z-heldout2-sys2b-routed.json)). The blind run is reported unchanged; the same frozen cases were re-run after the fix and are labelled as such |

## Review logic

| Issue                                                              | What happens                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         | How it was resolved                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| ------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| A note's document number was not compared with the customer record | A note with a check reference, a document number and a date met the standard even if the number was not one of the customer's documents.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             | **Fixed.** One count inside Zetaris under the evidence identity; only the count returns and the number is never logged (a hash is). A count of 0: "document cited in note not on customer record", the note does not meet the standard and a close goes to NEED_MORE_INFO. A count that cannot be made is "not verified" and fails closed. Sample mode has no saved answer for this count until the sample cache is recorded again, so there the check is "not verified".                                                          |
| Critic deadlock on citations that cannot be checked                | The decision step cited sources the critic cannot verify by design (a free-text column, the identifier number column, blocks worked out by code cited as tables). The critic rejected the same citation in every round, the decision repeated it, and the case ended unresolved and escalated.                                                                                                                                                                                                                                                                                                                                                                       | **Fixed.** The decision prompt lists exactly which tables and columns can be cited (the critic's tables, without free-text columns or the identifier number; the computed blocks named as not citable). The critic's note says "remove this citation; it cannot be cited", and from the second round on it sets such citations aside as not citable (in the trace, the record and the review desk) and checks the remaining facts. A citable fact whose value does not hold is still a rejection, and the three-round limit stays. |
| The span-grounding rule is too strict for the model's offsets      | Measured once on held-out v3 (frozen before the fix): the screener flagged two real relationship notes (a son, a nominee) at 0.9, but grounding marked both signals not grounded. The decision first escalated, citing them; the critic rejected those citations as not citable (screener facts are worked out by code); the decision's second answer was a close, the critic approved it, and under policy 7 the guard let it stand because the signals were not grounded (2 of 6 risk cases wrongly closed). The critic's citation rule is unchanged (feature freeze); under policy 8 the guard blocks such a close. The fix was made after held-out v3 was frozen | **Decided (policy 8).** The window was not widened and v3 was not re-run (a decision, so that v3 stays as run). Instead policy version 8 fails closed: grounding cannot set a signal aside, so a short span cannot let a risk case close. Measured once on held-out v4: no risk case closed                                                                                                                                                                                                                                        |
| Trace wording fix, no decision change: the fast-path line          | The triage line said "earlier clearance still valid: fast path" whenever the fast path was taken, also when there was no earlier decision and code's first finding settled the case, so it could follow "no earlier decision about this pair".                                                                                                                                                                                                                                                                                                                                                                                                                       | **Fixed.** Trace wording fix, no decision change: the line names the reason that held, "earlier clearance still valid" or "the structured evidence settles it". All 82 sample alerts were run with both wordings: answers and decision records identical, traces identical except the 47 reworded lines (and each run's own record id). The replay pages of ALR-0004, ALR-0030, ALR-0043 and ALR-0058 in `site/runs/` replay recorded traces, so they show the original line.                                                      |
| The ownership rule was effective ownership only                    | Percentages were multiplied along a chain, so a company 70% held by a holding company that a listed party owns 60% of came out at 42% and could be closed; under OFAC's rule it is blocked                                                                                                                                                                                                                                                                                                                                                                                                                                                                           | **Fixed.** The 50 percent rule is counted as a cascade as well (see [Changes after the evaluation](EVALUATION.md#changes-after-the-evaluation)); the Zetaris definition has a version 2 that says so                                                                                                                                                                                                                                                                                                                               |
| The request-for-information draft could describe the match         | It was built from the model's text and filtered by patterns that missed words such as "listed party" and "match"                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     | **Fixed.** Fixed wording, a tipping-off check with a fixed floor, and a person's approval (see [Changes after the evaluation](EVALUATION.md#changes-after-the-evaluation))                                                                                                                                                                                                                                                                                                                                                         |
| A true match stopped getting a block recommendation                | A code change made after the first system's run (a first finding from code and a confirm or reason path) gave the decision step code's first finding, and `chooseDecision` in `packages/agents/src/sample-rules.ts` mapped a met true-match definition to ESCALATE_L2. The decision prompt says to confirm a settled finding, so the decision step stopped proposing RECOMMEND_BLOCK. Found by comparing the current system's run on the 70 cases with the first system's run: the true matches the first system blocked were escalated instead, which is acceptable for them, so nothing was wrongly closed.                                                        | **Fixed:** a met true-match definition is RECOMMEND_BLOCK (still two different approvers), checked first so nothing can turn it into a close; a counterparty match, a document-number match and a strong assessment stay ESCALATE_L2. Test: `packages/agents/test/first-finding-block.test.ts`. Sample gate: 16 of 82 sample alerts changed from ESCALATE_L2 to RECOMMEND_BLOCK. Re-measured on the 70 cases: [EVALUATION.md](EVALUATION.md#a-block-recommendation-regression-found-in-the-current-system-comparison).             |

## Platform limits the desk works around

These limits of the editions we had are still there; the desk handles each one, so none is an open issue. Open platform limits are in [KNOWN_ISSUES.md](KNOWN_ISSUES.md#open-platform-limits).

| Limit                                                                                                                                                                                                                                                                                                                                                                                                                   | What we did                                                                                                                                                                                                                                                                                                                                                   |
| ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Nightshift: a model route is retired.** A mode or cloud function that used to answer returns HTTP 410, `class_no_route` or a "Function not found" 404 wrapped in a 502                                                                                                                                                                                                                                                | The generator treats these as a dead route, tries the next configured mode once, then the Ollama backup; every attempt is reported with the mode asked for and the model that answered. The cloud lanes were pointed at Nemotron 3 Ultra                                                                                                                      |
| **Nightshift: answers repeated from a cache.** A prompt answered before comes back in milliseconds with `from_cache: true`                                                                                                                                                                                                                                                                                              | Evaluation runs use a separate app id (`METERLESS_EVAL_APP_ID`); cached answers are excluded from latency figures                                                                                                                                                                                                                                             |
| **Nightshift: cloud reasoning leaks into the answer.** The cloud model writes its reasoning before (or instead of) the JSON and can run out of tokens before reaching it; four of the 65 cases of an early run (the exam has 70 cases) ended with no usable decision in the first full run                                                                                                                              | Reasoning is bounded and asked for with the JSON last; the last JSON object is taken. A failed first try is retried on the fast lane, then on the Ollama backup with JSON-only output. If all three fail, the case is escalated with the reason "model decision unavailable" and counted separately; it is never closed                                       |
| **Nightshift: slow route for "rejected" wording.** A retry phrased as a rejection goes to a much slower route, and the proxy gives up after about 47 seconds                                                                                                                                                                                                                                                            | Retry notes are worded neutrally; reasoning budgets are small                                                                                                                                                                                                                                                                                                 |
| **Zetaris: every value is a string.** Numbers, dates and NULLs come back as JSON strings (NULL as `null`)                                                                                                                                                                                                                                                                                                               | The code casts explicitly; amounts and scores are parsed where they are used                                                                                                                                                                                                                                                                                  |
| **Zetaris: a column called `precision`** is stored with its backquotes and breaks the compiled model                                                                                                                                                                                                                                                                                                                    | The column is called `dob_precision`                                                                                                                                                                                                                                                                                                                          |
| **Zetaris: one statement per call.** A semicolon makes the parser fail                                                                                                                                                                                                                                                                                                                                                  | The SQL guard rejects it before sending                                                                                                                                                                                                                                                                                                                       |
| **Zetaris: a role needs a permission, not only grants.** The three runtime users were refused every table of the model ("does not have access to USL") although table-level `SELECT` grants existed. The platform's permissions guide says a non-admin role also needs the View permission on the Unified Semantic Layer under Management → Permissions, an interface setting with no SQL form in the command reference | Set in the interface; step-role check 85 of 85 (`zetaris/step-roles-check.json`). A refused role token is an error, and the API will not start live while a role is refused; `zetaris.fallbackOnDenied: true` (off by default) retries once with the admin key, visibly (`token_source: fallback`), for setup only. See "Access control" in `docs/ZETARIS.md` |
| **Zetaris: grants and rebuilt models.** Grants are recorded against a model by internal identifier, and model access set in the interface is emptied by a rebuild, so a rebuilt model can leave roles that look granted but cannot read                                                                                                                                                                                 | Roles and grants are left in place across rebuilds and the live role check (`npm run test:live`) shows whether reads work                                                                                                                                                                                                                                     |
